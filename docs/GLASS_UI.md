# WPF 工作台界面

新版界面使用同一套启动、账号、实例、资源与任务服务，采用窗口内的窄图标导航、左侧操作或二级导航面板、右侧内容区结构。原先参考图中的外置侧栏、三段悬浮胶囊和大磨砂主卡已经移除。

## 背景与层次

未设置壁纸时，主内容区、独立悬浮竖栏与右上角控制胶囊共用 Windows 桌面 Acrylic，竖栏使用独立的较低染色强度，比主面板更通透。设置壁纸后，图片及其模糊只绘制在主面板及右上角控制胶囊与主面板交叠角的裁剪容器内；竖栏与控制胶囊悬空在桌面上的部分不显示或采样该图片，继续使用独立桌面磨砂。主面板使用壁纸时退出原生桌面采样，竖栏与控制胶囊不随之退出。桌面磨砂受 Windows 能力、透明度与高对比度设置影响，不可用时在对应轮廓内回退实色。在“设置 → 个性化 → 背景图片”点击“选择文件…”指定图片或视频。点击“清除”恢复默认背景。

背景图片保留不透明度、居中、裁剪、拉伸、平铺和边缘对齐设置。主区与悬浮栏分别控制材质，不通过整窗透明度一起变淡。高对比度使用系统颜色。

卡片的壁纸采样锚定到壁纸宿主，监听卡片与宿主之间的相对变换；入场缩放、位移及页面过渡不会带着壁纸纹理一起滑动。相同宿主、尺寸、DPI、适配方式与模糊半径共用冻结的预模糊纹理，动画只更新采样坐标，不逐卡重新计算模糊。纹理仅对可见表面按需合并生成，每宿主最多保留六项、单项不超过 800 万像素或 4096 像素边长；卸载时释放变换监听、待执行准备操作及卡片持有的纹理引用。

视频壁纸由 Windows Media Foundation 在后台解码。主面板与磨砂卡片使用同一视频帧，在 WPF 的同一次渲染提交中更新。后台最多预缓冲四帧，解码器回到循环开头时，已经缓冲的画面继续按时间戳播放。视频纹理上限为 1920×1080，磨砂纹理上限为 320×240。系统解码器无法打开时，会使用 WPF 的兼容播放器及磨砂采样。最小化时暂停视频和界面的定时刷新。

默认主题为深色。主背景采用 `#181818` 深灰和默认 85% 的面板不透明度；侧栏、卡片及输入控件使用中性灰；强调色为系统蓝（深色 `#0A84FF`、浅色 `#007AFF`），白字对比度不低于 3:1 的粗大字号要求，选中态只用同色调淡化，不再引入第二种色相。文字与图标保持独立实色，不随背景一起淡化；已保存的主题及透明度选择继续生效。

模态弹窗、遮罩与模糊只占据主面板：弹窗在主面板内居中，不跨越与竖栏之间的透明间隙；只模糊主面板，竖栏保持清晰但在弹窗期间不接受输入。弹窗采样主面板的冻结快照制作局部磨砂，文字和按钮不施加模糊。确认或关闭后，输入立即归还主界面，模糊与遮罩平滑淡出，连续开关可反向。

## 新的呈现组件

页面、账号、列表、表单、任务按钮和菜单使用新的标准 WPF 呈现树。原有控制器和状态源保留在隐藏的加载树中，新控件通过明确的命令接口、输入同步及设置事务接入业务；源 UIElement 不会放入可见树。原 PCL 标识选项、官方主题推广、不再适用的整窗透明度设置与“功能隐藏”设置区不在新版显示。

动态列表保持按需加载。按钮点击、复选预览取消、输入校验、账号选择、设置保存、加载错误重试、资源详情及收藏更新继续沿用实际业务路径。原始页面与新呈现分别管理生命周期，关闭时释放绑定和事件。

本地模组行在首次选择、点击、键盘焦点或右键前连接原有延迟命令，不依赖先悬停鼠标，也不提前初始化全部离屏行。资源包与光影包沿用原管理页的选择、详情和文件位置动作；原理图目录的双击或 Enter 进入原目录流程，截图的点击选择、双击与 Enter 预览转交原缩略图控制器。

整合包导出的选项名称、说明和分组标题同步控制器写入的动态富文本；重新枚举资源包等内容时会更新显示。读取导出配置后，“重置”按钮恢复原选项列表，“开始导出”继续调用原有导出流程。

资源分类页采用具体资源类型标题、搜索框与筛选设置单行、下展筛选及平铺结果列表。原版本、来源、类型和加载器选项保留原状态与搜索接口。条目显示原图标、标题标签、版本来源与真实下载计数；下载服务端等客户端范围外动作不出现在新呈现中。

账号头像沿用已加载的皮肤裁片，脸与帽层在同一像素网格合成。竖栏使用 32 DIP 图像和最近邻缩放；账号面板保留原皮肤图像的缩放方式，避免像素头像被平滑拉糊。

## 控件与字体

正文使用 Segoe UI Variable Text（中文回退 Microsoft YaHei UI），14 DIP；页面与面板标题使用 Segoe UI Variable Display。控件文字使用常规字重：雅黑没有中等字重，SemiBold 会直接渲染为粗体，只用于标题和主要操作。

按钮、下拉框与输入框采用同一外形：8 DIP 圆角、中性填充、上亮下暗的层次描边，悬停与按下在原填充上叠加前景色，不替换底色。输入框获得焦点时底部显示强调色细线，与占位文字左对齐。下拉列表从字段下方滑入淡入，箭头随展开旋转，当前项左侧显示强调色竖条。勾选框统一采用 20 DIP 立体凹槽双层键帽框设计（未勾选呈现内嵌微凸台，勾选时以弹簧展开外框光环与内层实心核，并同步沿路径渐进绘制对勾，不使用胶囊拨动开关）。互斥选项使用圆形单选标记；同一行的四种主页模式按分段控件显示。滑块的已选轨道和滑块中心使用强调色。

不确定进度的加载使用立体方块动画：淡色的等轴测立方体轮廓（六边形外框与汇聚于中心的三条棱，顶面略亮），一串圆点沿六边形外轮廓循环，尾迹大小与透明度按 (1 − offset)^0.56 衰减，轮廓轻微呼吸。思路参考 [Math Curve Loaders](https://github.com/Paidax01/math-curve-loaders)，代码独立实现。系统减少动画时只显示静止帧；已知进度时在动画下方附加细进度条。

## 导航与首页

主导航位于窗口内最左侧。具体页面的二级选项出现在其右边的纵向面板：原页面的分类小字（如“社区资源”“版本工具”）作为分组标题，一次性操作行（如“添加已有文件夹”“导入整合包”）以次要样式显示，行内附属按钮（刷新、配置）在悬停或键盘焦点时出现，右键沿用原菜单。旧的“全部页面选项”弹层已移除。资源详情、帮助详情等详情页保留来源页面（资源中心、收藏、实例管理等）的侧栏与竖栏选中；点击侧栏分类直接返回对应列表。右侧顶部显示必要的页面标题和返回入口，最小化和关闭按钮位于向右上错出主面板 `10 DIP` 的独立毛玻璃悬浮胶囊中。新版不应用旧的功能隐藏偏好，F12 也不再切换该状态；经典界面的行为与已保存偏好保持不变。

首页左侧面板从上到下放置标题与加号、当前游戏实例图标和名称、启动/取消按钮；底部左右分别为选择实例和实例管理。首页右侧默认留空，只显示启动器背景；点击加号后才向右展开依赖检查和最近游玩。最左导航默认保持 `64 DIP` 窄栏，支持点击底部展开/收起按钮以快速欠阻尼 iOS 弹簧动效向屏幕左侧外扩展开至 `168 DIP`（主面板位置与宽度完全固定不动，竖栏右边缘锚定在距主面板 `12 DIP` 处，向左展开显示 `PCL-LF` 现代几何字标、各导航文字标签及当前账户名称，再次点击向右回弹收起）。最左导航与主面板顶部齐平且内缩 `10 DIP`（主面板右侧同内缩 `10 DIP` 以容纳错位控制胶囊），两者相隔 `12 DIP`，三块独立外轮廓均为 `12 DIP` 圆角，间隙与圆角之外保持透明。竖栏顶部放应用 Logo、底部放登录角色头像；收起态下头像左右及底部留白一致，Logo 左右及顶部留白一致，并随 DPI 舍入。首页底栏只保留选择实例与实例管理。任务管理沿用原版 PCL 的方式，在存在任务时由右下角悬浮按钮进入；音乐按钮同样按原条件出现。

外轮廓使用抗锯齿透明度遮罩，保留边缘的分级 alpha；原生窗口区域只排除两面板之间的空隙，避免 GDI 的整数圆角切掉平滑边缘。透明像素的窗口命中遵循 Windows 分层窗口机制。实现依据见 [WPF 透明度遮罩](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/graphics-multimedia/opacity-masks-overview) 和 [Windows 分层窗口](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features)。

## 设计参考与动效

交互经验参考 [Apple Design](https://developer.apple.com/cn/design/) 中的清晰层级、即时反馈与连续过渡；桌面表单和键盘使用参考 Windows 的焦点及可访问性规范。动效集中于按压反馈、选择变化和页面状态过渡，保留可打断与快速反向；键盘操作和系统减少动效即时完成。

## 选中、提示与滚动

新界面不使用液态玻璃材质。竖栏与二级侧栏的选中位置是一层与面板同色调的叠层（深色略亮、浅色略暗），选中文字使用强调色；切换时叠层以弹簧滑到新位置，二级侧栏的弹簧略欠阻尼以柔和落定。按钮保持平面填充，不使用渐变高光。

提示沿用原版队列、去重与计时，由主面板右下角的提示卡片镜像显示：圆角卡片、阴影和按原色调识别的信息/成功/错误图标，以欠阻尼弹簧从右侧滑入并放大，离开时高度收拢，下方卡片平滑上移；悬浮任务按钮出现时整体上移让位。

主内容与侧栏的滚轮滚动带惯性：每格推进目标位置，视口以指数缓动滑向目标，连续滚动累积速度；拖动滚动条或键盘滚动立即接管，嵌套滚动区优先处理指针下方的区域。页面级滚动区的上下边缘在仍可滚动时柔和渐隐：内容本身沿平滑曲线淡出（顶部 56 DIP、底部 48 DIP），强度随剩余可滚动距离平滑增长，不叠加模糊副本，因而没有重影或分界线。页面切换使用柔和的欠阻尼弹簧，并按导航顺序决定方向：沿竖栏或侧栏向下切换时新页面自下方 22 DIP 进入，向上切换时自上方进入，旧画面提前淡出并反向轻移。新页面的卡片与列表项、换到另一栏目后的侧栏标题与各行按列表入场节奏依次出现：每项自 96% 缩放、下方 14 DIP 与透明开始，330 ms 三次缓出，相邻项间隔 30 ms，最多累计 12 级。系统启用减少动效时跳过入场动画。入场的初始状态在首帧绘制前同步设置，不会先显示完整内容再闪入；过渡按帧推进且单帧最多前进 1/40 秒，UI 线程短暂卡顿时动画暂停后继续，而不是直接跳到终点。过渡进行时外壳推迟整页重投影。

切换栏目或子页面时，外壳以显示容器中实际出现的页面为准开始过渡（子页面会先指定、约 130 ms 后才放入容器）；在新页面到达前，页面标题与侧栏标题保持不变，正在显示的旧页面也不随原页面的退场而清空，交叉淡入从真实内容开始。等待超过约 0.6 秒时恢复正常刷新。

页面内提示沿用原版三种语义：蓝色为说明、黄色为注意、红色为警告。提示以对应色调的浅色底、左侧色条和同色圆形图标区分，文字保持正常对比度，关闭按钮为细线“×”；高对比度下使用系统颜色。

内存分配显示为一条分段条：系统已用（中性色）、游戏分配（强调色，超过剩余可用内存时改为警示色并给出说明）与剩余可用，下方图例给出三项数值和总量；数值读取原控件的列比例与文字。

下载页（版本列表、资源列表与资源详情）的条目右侧不显示安装/下载标签、日期和下载量；资源条目保留收藏按钮。点击条目沿用原安装或打开详情动作，版本条目的另存为、更新日志移入条目右键菜单。

## 验证

需要 .NET 10 SDK 和 Windows WPF 环境：

```powershell
dotnet build tests/PCLLF.Native.Facade.Tests/PCLLF.Native.Facade.Tests.csproj -c Debug
$env:PCL_NATIVE_REPOSITORY_ROOT = $PWD.Path
dotnet run --project tests/PCLLF.Native.Facade.Tests -c Debug --no-build -- --groups glass-shell
dotnet run --project tests/PCLLF.Native.Facade.Tests -c Debug --no-build -- --groups glass-window
dotnet run --project tests/PCLLF.Native.Facade.Tests -c Debug --no-build -- --groups glass-presentation
dotnet run --project tests/PCLLF.Native.Facade.Tests -c Debug --no-build -- --groups glass-portals
dotnet run --project tests/PCLLF.Native.Facade.Tests -c Debug --no-build -- --groups glass-account-ui
dotnet run --project tests/PCLLF.Native.Facade.Tests -c Debug --no-build -- --groups workbench-commands
```

历史检查组名称保留以兼容 CI。新窗口验收检查前景 HWND 中三块表面（竖栏、主面板与错位窗口控制胶囊）的命中范围、抗锯齿半透明边缘、透明间隙/错位空隙及角点、桌面材质下的背景透明度、关闭材质后的实色回退、启动器壁纸、前景文字不随背景淡化、头像与 Logo 对称留白、原命令接线、缩放、最小化恢复和清理。账号自动化使用实际认证引擎与加密事务，但账号和传输为合成夹具，不代表真实微软授权或 Minecraft 游戏内运行已验收。
